# Progress Tracker — Braindump

- The fundamental thing MediaFlow needs to know: "where am I in this thing."
- For a book it's a page. For a TV show it's an episode. For a game it's hours. For a movie it's basically binary (watched or not).
- The temptation is to have a separate tracker per media type. That ends in five widgets, five APIs, five sets of bugs.
- One model. ProgressRecord with media_type and a JSON details column. Cleanest.
- Yes, JSON in a relational store is "not pure." Fight me. The query patterns we care about ("all my in-progress items") all live at the row level, not inside the JSON.
- Unit display: do I show "page 247 / 412" or "60%"? Both. Native unit is what humans think in; percentage is what the bar fills.
- Update has to be fast. One click. If it takes a modal I'll never log my progress and the data rots.
- Inline stepper on the card. +1 / -1. Maybe a tap-and-drag for big jumps later.
- TV episodes are weird. Season X episode Y. You're either "watching" the show or you're not. Pause means dormant.
- Multi-device sync: I read on my Kindle (eventually), I track on my phone. Same item, different devices, both updating. Conflicts are real.
- Naive approach: last write wins. Bad — could regress progress if my phone is offline and pushes stale data on reconnect.
- Better: take the higher value. You don't un-read pages. (Unless you DNF — but that's an explicit action, not a progress update.)
- For games: Steam hours sync from import. If they go DOWN (refund) we should at least notice.
- MVVM. Task-12 forces it for new features and that's fine — progress is exactly the kind of feature where you want viewmodel logic out of the JSX.
- progress.model.ts → just the types and the data shape. No logic.
- progress.view.tsx → the bar widget, props in, no state of its own.
- progress.viewmodel.ts → the hooks, actions, optimistic updates, the actual machinery.
- Optimistic update is mandatory. User clicks +1, bar moves NOW. If the server rejects we revert + toast.
- Stagnation: I have books on my "currently reading" shelf I last touched 4 years ago. Be honest with me.
- 30 days seems like a reasonable threshold. Nudge ONCE. Options: continue, pause, abandon. Default to pause if ignored.
- Don't make the stagnation prompt aggressive. One toast, then leave me alone.
- Completed items: green checkmark, dimmed cover. They stay in the list. I want to scroll past my history.
- "Move to completed tab" was the alternative — rejected, I always end up checking back.
- Achievements: NOT in v1. Tempting for games but it's a rabbit hole (icons, tracking, sync from Steam/Xbox/PSN, etc).
- Reading-time prediction: "you'll finish this in 4 hours." Cute but v2. Need data first.
- Conflict resolution UI: probably non-existent in v1. Server-side rule of "max(local, remote)" handles 95% of cases.
- Need to write E2E for the multi-device path before this ships. Spin up two browser sessions.
- One thing I want to avoid: tracking that the user has to babysit. If logging progress feels like a chore, nobody does it, and the rest of the product loses its signal.
