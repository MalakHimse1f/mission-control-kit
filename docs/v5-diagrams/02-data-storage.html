control/
.mc/ Runtime state — ephemeral, not committed
├── orchestrator-controls.json User preferences
Persisted user prefs: verbosity, auto-approve, active feature
├── dashboard-server.json Server PID / port
Tracks running dashboard server process for lifecycle management
└── ralph/ Loop state
Ralph orchestrator loop state — iteration count, current step, errors
features/{slug}/ One directory per feature — fully self-contained
├── status.json Pipeline stage, current task
Machine-readable status: which pipeline stage, what task is active
├── decisions.json User choices new in v5
Captures user decisions at each checkpoint — prevents re-asking
├── braindump.md Initial capture (short)
Raw user input — the original idea, kept brief and unprocessed
├── spec.md PRD (focused)
Product requirements document — structured, under 200 lines
├── ux-flow.html Interactive UX diagram
Self-contained HTML showing user flows — click-through prototype

Integration requirements, API contracts, constraints
└── phases/ Integration plans
Phased integration plan — phase-1.md through phase-N.md

Master index: given a task type, which documents to read/write

Standards for UI tasks — component patterns, accessibility, responsive
├── UX-PATTERNS.md UX-specific guidance
User flow patterns — navigation, onboarding, error handling

System design patterns — data flow, service boundaries, APIs
