Data Flow — "Start" from Cloud Dashboard
1
User clicks Start on a feature card Web App
Dashboard reads feature's current stage from cloud state, e.g. stage: braindump or stage: build-phase-2.
2
Orchestrator API picks the action Cloud
Maps stage → command. Interactive stage (Q&A) opens chat in browser. Build stage runs subagent-driven development on the machine. Sends a spawn-session event to the user's bridge.
3
Bridge daemon receives event Local
Verifies device + org token over WebSocket. Resolves the local repo path from .mck-link. Confirms workflow & standards cache is up to date.
4
Bridge spawns Claude Code / Cursor Local
Launches the user's chosen agent with the right command: /mc, /mc-feature {slug}, or build resume. Hooks pipe transcript & tool calls back to the bridge.
5
Agent runs the org workflow Local
Orchestrator skill reads cached org workflow. Router builds context packet — pulls only the docs the stage needs, plus the org's standards block. Dispatches subagents.
6
Bridge streams everything back Local
Journal lines, status diffs, decisions, and assistant messages flow up. For interactive stages, the web chat panel becomes the Q&A surface — user can answer from anywhere.
7
Org dashboard updates live Web App
Stage, progress, and blockers update in real time for every viewer. Other org members see the agent running. Portfolio order recomputes.
