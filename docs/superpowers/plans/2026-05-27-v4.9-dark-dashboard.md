# v4.9.0 — Clean Dark Dashboard + Feature Pages — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the generated dashboard in the v4.8 selection-deck design language (dark palette), move the "How to use" guide to the bottom with per-command copy buttons, and replace the feature **modal** with a single-file, hash-routed feature **page** that has a Back button.

The feature page reuses the existing `detail-*` element IDs and `openDetail(id)` population logic — only the open/close mechanism changes (view-swap + `#feature/<id>` hash instead of a modal overlay).

**Tech Stack:** Node ESM, `node --test` runner (`npm test`), plain inline HTML/CSS/JS in template strings. No framework.

**Source-of-truth prototype (approved in brainstorming, persisted on disk):**
`.superpowers/brainstorm/10533-1779920031/content/dashboard-nav-v1.html` — the target dark aesthetic + working nav/copy behavior. `.superpowers/` is gitignored, so the tokens/JS below are reproduced inline.

Run `npm test` before each commit; the only acceptable failure is the pre-existing `release-bundle.test.mjs` "builds tarball" tar quirk on Windows.   function copyCmd(btn){
    var text = btn.getAttribute("data-cmd");
    function ok(){ var t=btn.textContent; btn.textContent="Copied ✓"; btn.classList.add("done"); setTimeout(function(){btn.textContent=t;btn.classList.remove("done");},1200); }
