# v4.9.0 — Clean Dark Dashboard + Feature Pages

**Date:** 2026-05-27
**Base:** v4.8.0 (branch `v4.7.1-base` / `main`)
**Status:** Design — pending user review

---

## 1. Context & motivation

The dashboard (`control/dashboard.html`, generated by `control/scripts/dashboard-*.mjs`)
works but its dark theme is busy and dated, and feature detail opens in a cramped
modal. v4.9 restyles it in the clean **selection-deck design language** (shipped in
v4.8 under `control/layout/selection/`) — but in a **dark** palette — and replaces the
modal with a real, navigable **feature page**.

Three user-requested changes:
1. **Clean dark dashboard** modeled on the selection-deck aesthetic (not light — dark).
2. **"How to use Mission Control"** moved from near-top to the **bottom**, with **copy
   buttons** for each command/skill.
3. Clicking a feature **navigates to a feature page** (not a popover); the page has a
   **"Back to dashboard"** button in the top-left.

Approved visual prototype: `.superpowers/brainstorm/10533-1779920031/content/dashboard-nav-v1.html`
(gitignored; §4–§6 capture the contract so it survives if that dir is cleaned).

## 2. Goals / non-goals

**Goals**
- Restyle the dashboard to the selection-deck design language in a dark palette.
- Move the guide to the bottom, collapsed, with per-command copy buttons.
- Replace the feature modal with a single-file, view-swap + hash-routed feature page.
- Preserve the **single self-contained file** model (opens via `file://`, no server).
- Keep the data layer untouched (same `window.MC_ITEMS` shape).

**Non-goals**
- No change to `dashboard-data.mjs` / `dashboard-content.mjs` data collection.
- No multi-file output, no server-only routes (the file must still open standalone).
- No change to what content a feature shows — only how it's presented (page vs modal).
- No restyling of the embedded research/wireframe HTML (those stay self-contained light
  documents inside dark frames).

## 4. Dark theme (design tokens + components)

Replace the current `:root` palette and component CSS with the deck-derived dark set:

```
--bg:#0f0f11; --panel:#17181b; --panel-2:#1c1d21; --raised:#212227;
--ink:#ededee; --ink-soft:#a6a7ac; --muted:#6f7177;
--line:#2a2c31; --line-2:#3a3d44;
--accent:#e8e8ea;  /* near-white primary button / current-step */
--ok:#7fb38a; --warn:#c9a86a; --stop:#c98a8a;  /* desaturated status */
```

Component rules (match the prototype):
- **Cards** — `--panel` bg, `--line` border, 12px radius, hover → `--panel-2` +
  `--line-2` border, subtle `translateY(1px)` on active. Contents: feature name (`h3`),
  small uppercase "Feature/Setup" kind label, status **chip**, thin **progress** bar
  (`#0c0c0e` track, `--ink-soft` fill), current task + relative timestamp, action
  buttons.
- **Chips** — pill, `--line-2` border, `--ink-soft` text; variants `build` (cool
  tint), `done` (`--ok`), `blocked` (`--stop`).
- **In-progress strip** — plain `--panel-2` panel, `--line` border, **no left accent
  border**, with name + task + mini progress + stage chip.
- **Primary button** — `--accent` bg, `#161616` text (the single bright element).
- **Secondary button** — transparent, `--line-2` border.
- Section labels — 11px uppercase, `.14em` tracking, `--muted`.
- Typography: system sans, antialiased, sizes per prototype.

`color-scheme: dark`. No behavioral change from this section.

## 5. Guide → bottom, with copy buttons

`dashboard-guide.mjs` emits a `<details class="guide">` rendered **after** the "All
work" grid (was 3rd from top), **collapsed by default** (no `open` attribute). Content
is a list of **command rows**, each: `<code>` (e.g. `/mc-feature`), a description, and a
**Copy** button calling `copyCmd(btn, '/mc-feature')`. Commands covered (match current
guide): `/mc-init`, `/mc-feature`, `/mc`, `/mc-portfolio`, `/mc-upgrade` (plus any others
the current guide lists — preserve coverage). The disclosure twisty rotates on open.

## 6. Feature page (replaces modal)

The generated file contains **two top-level views**:
- `#view-dashboard` (`.view.active` initially) — topbar, in-progress, work grid, guide.
- `#view-feature` — `‹ Back to dashboard` button (top-left), feature title + status
  chip, pipeline step row, then the detail panels.

**Navigation (client JS, single file):**
- `openFeature(slug)` — populate the feature view from the item's data (looked up in
  `window.MC_ITEMS` by slug), `history.pushState({slug}, '', '#feature/'+slug)`,
  activate `#view-feature`, scroll top.
- `goDashboard()` — `pushState({}, '', '#')`, activate `#view-dashboard`.
- `popstate` handler — read `location.hash`; `#feature/<slug>` → show that feature,
  else show dashboard. Makes the browser Back/Forward buttons work.
- On load — if `location.hash` matches `#feature/<slug>`, deep-link straight to it.
- A card's `onclick` calls `openFeature(slug)`; inner action buttons call
  `event.stopPropagation()` so "Pickup" doesn't also navigate.

**Detail rendering reuse:** the feature view is populated by the existing renderers
(`renderStepTimeline`, `renderDocBlock`, `renderResearchPages`, `renderWireframes`,
`renderTasksTable`, `renderCollapsibleDocs`, pickup-prompt copy) — moved from the modal
body into the feature view container. The "Copy pickup prompt" action is preserved.

**Removal:** delete the `.modal-overlay` / `.modal-dialog` markup, its CSS, and the
`openDetail` / close-on-Escape / `modal-open` body-lock handlers. Replace all
detail-open triggers with `openFeature`.

**Embeds:** research/explore/wireframe HTML continues to embed via `<iframe srcdoc>`
(self-contained light documents) inside dark `--panel` cards — unchanged.

## 9. Risks & open questions

- **Clipboard in iframe/file://** — `copyCmd` uses `navigator.clipboard` with a
  select/`execCommand` fallback (same pattern as the v4.8 decks), so copy works on
  `file://` and in the dashboard.
- **Server regen** — `dashboard-server.mjs` serves the same generated HTML; the
  view-swap is client-side, so the server needs no route changes. Confirm a served
  dashboard still deep-links on `#feature/<slug>`.
- **Large `MC_ITEMS`** — feature lookup by slug must handle items without a slug
  (setup/tech-stack rows); fall back to id.

## 10. Success criteria

1. Dashboard renders in the clean dark selection-deck aesthetic; in-progress strip has
   no left accent.
2. The guide sits at the bottom, collapsed, every command row has a working Copy button.
3. Clicking a feature opens a feature page with a top-left Back button; the browser Back
   button and `#feature/<slug>` deep links work; no modal remains.
4. The file still opens standalone (`file://`) with all content embedded.
5. Tests green (except the known tar quirk); version is 4.9.0.
