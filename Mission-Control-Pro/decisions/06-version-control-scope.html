"Version control everything" can mean five different things.
How rich is v1?

The problem Workflows, standards, and primitives all need history. But "version control" spans from "every save is a new row" to "Git-like branches with PRs." The richer we go, the more we have to design (diff UI, merge UI, conflict resolution). Pick the level v1 ships.
Decided 2026-05-26 · Linear history + one draft per author

Every save creates a new immutable version pointing at the previous one. Each author can have one in-progress draft per workflow; drafts don't affect any agent. In-flight agent sessions pin to version_id at start. No branches, no merge UI in v1.
