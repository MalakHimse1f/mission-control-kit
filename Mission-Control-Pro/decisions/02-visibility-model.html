Visibility model — journal-driven, not transcript-driven.

The original concern Claude Code does not expose the live transcript to external processes. If we wanted "the cloud sees what the agent is doing," we had three options: capture journal entries the orchestrator skill explicitly writes (small, structured), mirror the entire chat (impossible without changes to Claude Code), or try a hybrid. We needed to pick one.
Resolved 2026-05-26 · Journal-driven

The cloud sees only what the orchestrator skill and subagents explicitly journal — plus structured decide events that pause the agent. Free-form chat stays in the IDE. The web and mobile surfaces answer the structured moments; everything between is the user's private workspace.

Hooks must be unbypassable. They are the contract that important moments were journaled. If a subagent forgets to journal, the cloud doesn't know it happened — so journaling is enforced at hook boundaries, not by convention.

✓ Journal-driven
What flows to the cloud
Two channels only
Journal events — explicitly written by orchestrator + subagents
Decision requests — emitted by decide step type
Free-form chat transcript — never
File contents — never (unless explicitly attached)
Tool call arguments — never
Implications
  • The bridge protocol carries structured events, not text streams
  • Dashboard visibility is bounded — what's journaled is what's seen
  • Privacy is enforced by what the skill writes, not by post-hoc filtering
  • "Answer from mobile" only works when the workflow uses decide
Hooks are load-bearing
  • Every important moment must journal — hook boundary enforces it
  • Workflow steps that forget to use decide won't surface to mobile
  • The orchestrator skill is the contract — bugs there hide events
