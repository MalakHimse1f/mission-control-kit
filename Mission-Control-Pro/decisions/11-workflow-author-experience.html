Workflow authors are our power users.
What's their feedback loop?

The problem A workflow author writes a workflow, saves it in the cloud, and then has to launch a real agent on a real repo to see whether it does what they expected. If that loop is "edit → save → wait for sync → start agent → see what happens" it'll be slow enough that authors give up. The people who become champions need a tighter feedback cycle.
Decided 2026-05-26 · Path B

mcp lint CLI ships in the bridge installer; validates workflow files against the schema. Bridge tray exposes "Preview dispatch" — builds and prints the context packet on a chosen repo without invoking Claude. Sub-minute feedback for syntax and routing. Cloud sync via CLI (mcp pull / push) is explicitly v2.
