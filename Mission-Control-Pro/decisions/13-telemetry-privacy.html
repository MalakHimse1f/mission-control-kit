Product telemetry helps us improve.
Customer privacy is non-negotiable.

The problem We want to know which workflow templates get used, where onboarding stalls, and how often agents finish their flows. Customers — especially enterprise — want explicit control over what leaves their environment. Pick a default that respects both sides.
Decided 2026-05-26 · Path B

Opt-in only. Nothing leaves customer environments unless explicitly enabled. Settings show a clear "Send anonymous usage data" toggle (default off). Content telemetry never exists. Tradeoff: very little wild usage data — onboarding optimization comes from design partners + sales conversations. Telemetry infrastructure is still built (Edge Function + schema) so opting in is a flip.

Decision

What's the default telemetry posture, and what's the opt-out?

A Not chosen
Usage on by default · content always off · single per-org toggle
Anonymized usage events (which CTAs, which workflows started, which steps stalled) are on by default. Content telemetry (decision bodies, journal text) is *never* sent regardless of setting. Org-wide toggle in settings can disable all usage telemetry.
Two clear lanes
Usage events — on (opt-out)
Content — always off
↓ org toggle
Settings → "Send anonymous usage data"
Pros
  • We get the data we need for product
  • Content is never at risk
  • One toggle is easy to understand
Cons
  • Some customers will still want opt-in only
  • Need a clear written policy
B Decided
Opt-in only · no telemetry by default
Nothing leaves customer environments unless explicitly enabled. Strongest privacy posture.
Opt-in default
All telemetry — off
↓ admin opts in
Then usage events flow
Pros
  • Best for enterprise reviews
  • No ambiguity about consent
Cons
  • ~5% of orgs ever opt in
  • Hard to learn from real usage
C Not chosen
Three-level slider — off / usage / usage+content
Admin picks: none / anonymous usage / usage with content samples. Content samples can include redacted decision bodies for debugging.
Slider levels
○ Off
● Usage only (default?)
● Usage + content (debug)
Pros
  • Lets power users help with debugging
Cons
  • Content telemetry is dangerous
  • Three options = more confusing UI
  • Legal review of "redaction" claims
Implementation notes if Path A is chosen Telemetry events go through a separate Edge Function endpoint (not the same channel as agent journal). Schema is event-name + small property bag (no free text). Org setting orgs.telemetry_enabled boolean default true. Self-hosted bridge fleet (Enterprise) defaults to false. Public telemetry catalog (a docs page listing every event we capture) ships with the product.
